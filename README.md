# 航段时间清洗 · DST 安全入仓

面向航司数据工程师的网页工具：把地服导出的**当地时间**航段链解析为唯一 **UTC** 时间链，
避免夏令时（DST）切换时被错误入仓；并支持把**地服与航司值班员各自改过的两份更正 CSV**
合并成一份新的当地时间底稿，核对通过后再交回原清洗流程入仓。

## 快速启动

```bash
docker compose up --build
```

浏览器打开 <http://localhost:8000> ，顶部两个页签：

- **① 清洗页**：点击「📦 载入内置夏令时样例」→「开始清洗」查看完整求解演示；
- **② 更正合并**：点击「📦 一键载入合并样例（三份）」→「开始比对合并」，
  体验自动合并、冲突选值、改选重核对与下载闸门。

本地开发（不用 Docker）：

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

自检（仅标准库）：

```bash
python3 tests/test_solver.py   # 清洗求解器
python3 tests/test_merger.py   # 三方合并 + 下载闸门
```

## 输入 CSV 格式

UTF-8 编码，必需表头：

```csv
tail_number,seq,dep_local,dep_tz,arr_local,arr_tz,duration_min_minutes,duration_max_minutes
B-7001,1,2026-10-25 00:30,Europe/London,2026-10-25 02:15,Europe/Berlin,90,130
```

| 列 | 含义 |
| --- | --- |
| `tail_number` | 机尾号（同一机尾构成一条航段链） |
| `seq` | 航段顺序，整数，同一机尾内唯一，按升序链接 |
| `dep_local` / `arr_local` | 起飞/落地当地时间，`YYYY-MM-DD HH:MM`（也接受 `T` 分隔与秒） |
| `dep_tz` / `arr_tz` | 两端 IANA 时区名，如 `Europe/Berlin`、`America/New_York` |
| `duration_min_minutes` / `duration_max_minutes` | 飞行时长下/上限（分钟，**闭区间**） |

## 求解规则

1. 当地时间 → UTC 候选：
   - 普通时刻 → 1 个候选；
   - **重复时刻**（秋季拨回重叠，如柏林 2026-10-25 02:30）→ 保留 **2 个候选**参与整链求解；
   - **不存在的时刻**（春季拨快空洞，如柏林 2026-03-29 02:30）→ 该行报错，整架机尾禁止导出。
2. 每个航段的 (起飞, 落地) 候选组合必须满足：飞行时长 ∈ `[下限, 上限]`（闭区间）。
3. 按 `seq` 链接同一机尾：下一段起飞 **不得早于** 上一段落地（相等允许）。
4. 判定：
   - **整链唯一解** → 允许导出该机尾的 UTC CSV；
   - **无解** → 展示冲突航段（前向扫描定位第一个无法衔接的航段及其候选），禁止导出；
   - **多解** → 展示全部可行候选链（最多展示 20 条），禁止导出；
   - **行级错误**（不存在时刻 / 非法时区 / 格式错误 / seq 重复等）→ 禁止导出。

## 导出

- 网页上按机尾导出，或「导出全部可导出机尾」；
- 导出列：`tail_number,seq,dep_utc,arr_utc,duration_minutes`（UTC 为 ISO 8601 `Z` 格式）；
- 服务端在导出时会**重新求解并复核唯一性**，非唯一解返回 409，杜绝误导出。

## 地服 / 航司 两份更正合并（清洗页 → 「② 更正合并」页签）

### 输入

上传三份 CSV，均沿用清洗表头：一份**底稿**、一份**地服更正**、一份**航司值班员更正**。

- 三份文件必须包含**同一组航段**，以 `tail_number + seq`（机尾号 + 航段序号）定位；
- 每份文件内定位键不能重复，否则整单拒绝并指出机尾 / seq；
- 航段组不一致（缺航段、多航段）同样拒绝，并列出差异定位键。

### 逐字段合并规则

对照底稿逐字段判定（参与比对的为除定位键外的 6 个字段）：

| 情况 | 状态 | 处理 |
| --- | --- | --- |
| 两边都没改 | `unchanged` | 保留底稿值 |
| 仅地服改 | `auto_ground` | 自动取地服值 |
| 仅航司改 | `auto_airline` | 自动取航司值 |
| 双方都改且值相同 | `auto_agreed` | 自动取该值 |
| 双方都改且值不同 | `conflict` | 值班员从**三份文件给出的值**里选一个 |

- 冲突格下拉框只列出三份文件出现过的去重值（带来源标注），服务端对选值再次校验，
  传入三份文件之外的值返回 400；
- **自动合并的值也能改选**（含把单方改动改回底稿值），可选范围同样仅限三份文件的值。

### 重跑清洗与下载闸门

- 点「重新核对」后，服务端按当前合并稿，对**任一方改过的机尾**重跑整条航段链清洗，
  页面列出每个改过机尾的状态（唯一解 / 无解 / 多解 / 数据错误）及未通过原因；
- 只有同时满足：① 所有冲突均已选值；② 改过的机尾全部为整链**唯一解**，
  才允许点「⬇ 下载当地时间合并稿 CSV」；
- 任何改选都会把页面置为「须重新核对」，下载按钮禁用；
  `/api/merge/export` 服务端也会**重新核对一次**，不满足条件返回 409，杜绝绕过前端下载；
- 下载的 CSV 沿用清洗表头（当地时间），可直接作为原 `/api/solve` 流程的输入。

### 合并样例（samples/merge/）

三份文件里的每架机尾单独跑清洗都是整链唯一解（两份更正各自可用），但合并后会暴露问题：

| 机尾 | 场景 | 合并后结果 |
| --- | --- | --- |
| B-8001 | 地服把 seq=2 落地推迟到 15:20，航司把 seq=3 起飞提前到 15:00（各自单独都成立） | 自动合并后 seq=3 起飞早于 seq=2 落地，**整链无法衔接（无解）**；把 seq=3 起飞改选回底稿 17:30 即恢复唯一解 |
| B-8002 | 航司把起飞时区改到东京并放宽时长窗口，地服把窗口改成 `[45,135]`，与底稿 `[60,120]`、航司 `[150,240]` 三方互异 | 2 个**冲突字段**需选值；某些选值组合（上海时区 + 航司窗口）会让该机尾无解，被闸门拦截 |
| B-8003 | 双方都改了同一批字段，部分改成同一值、部分各改一处 | 全部可自动合并，重跑清洗为唯一解 |

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/` | 网页入口（清洗页 + 更正合并页） |
| `GET` | `/api/sample` | 下载内置清洗样例 CSV |
| `POST` | `/api/solve` | 上传 CSV（multipart 字段 `file`），返回逐机尾求解结果 JSON |
| `POST` | `/api/export` | 字段 `file` + `tail`（`__all__` 表示全部可导出机尾），返回 UTC CSV；非唯一解 409 |
| `GET` | `/api/merge/sample/{base,ground,airline}` | 下载合并样例三份 CSV 之一 |
| `POST` | `/api/merge/analyze` | 字段 `base` / `ground` / `airline` 三个 CSV，返回逐字段比对、自动合并结果与冲突清单 |
| `POST` | `/api/merge/verify` | 同上三个 CSV + `resolutions`（JSON 字符串 `{机尾:{seq:{字段:值}}}`），对改过机尾重跑清洗，返回 `download_allowed` 与全部阻断原因 |
| `POST` | `/api/merge/export` | 入参与 verify 相同；服务端重新核对，通过才返回当地时间合并稿 CSV，否则 409 |
| `GET` | `/docs` | FastAPI 自动文档 |
